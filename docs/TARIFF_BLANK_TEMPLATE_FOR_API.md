# Ask: a blank tariff template endpoint

Context: the UI is adding a **Download template** link on the tariff register
(`/tariff/plans`), before any schedule exists. Today the only template endpoint is
`GET /api/revenue/tariffs/{scheduleId}/template`, which needs a schedule and carries
that draft's rates plus an export token. A clerk starting a new customer's quotation
has neither.

Do not let the UI hand-roll the workbook. The file that gets parsed must be written by
the code that parses it, or the two drift the first time a column is added and every
tenant's clerks get a file the server rejects.

## 1. New endpoint

```
GET /api/revenue/tariffs/template
→ 200 application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
  Content-Disposition: attachment; filename="Gecko-Tariff-Template.xlsx"
```

- No schedule id, no rows — the same sheets, same column headers, same order as
  `/tariffs/{id}/template`, with the data rows empty.
- Generated by the **same writer** as the per-schedule template. One code path, one
  column contract. If the writer takes a schedule today, give it a null/empty overload.
- Permission: same as the existing template download (`revenue.import.manage`, or
  whatever guards it today). It leaks no customer data, so a plain tariff-read is fine
  if that is simpler.
- Tenant-scoped: the reference sheets below must be the caller's tenant.

## 2. What the blank workbook should carry

The template is the only training a depot clerk gets, so it has to be self-teaching:

- **Reference sheets** listing the tenant's current valid codes — charge codes,
  container types and sizes, order types, movement types, truck categories, cargo
  categories — each with code + description.
- **Data validation (dropdowns)** on the rate sheet's code columns, pointing at those
  reference sheets, so an invalid charge code cannot be typed in the first place. This
  is the single biggest reason to generate it server-side.
- **A header note or first comment row** stating the tier syntax the parser expects
  (`1-7:160; 8-14:275; 15+:390`) and that `RateKey` is left blank on new lines.
- `RateKey` present but empty (hidden column is fine), exactly as in the per-schedule
  template, so the same reader handles both.

## 3. The integration detail that will bite — please confirm

`/tariffs/{id}/template` embeds a token tying the file to that draft, and the preview
reports `scheduleChangedSinceExport`. **A blank template has no token.**

So: `POST /api/revenue/tariffs/{scheduleId}/imports` must accept a workbook with **no
export token** and treat it as a full rate set for that draft — every line an INSERT,
`scheduleChangedSinceExport` false (not "changed"), no 400 for the missing token.

That is the whole flow the UI is building:

```
register → Download template (blank)
clerk fills it in, offline, possibly for days
new quotation → save the draft header → upload the filled workbook
→ preview (all INSERT) → apply
```

Please confirm the tokenless upload path works, or tell us what the UI should send
instead. Everything else on our side is already wired to the existing
upload → preview → confirm/cancel contract; nothing there needs to change.

## 4. Not asked for

No change to `/tariffs/{id}/template`, `/imports/{batchId}/confirm` or `/cancel`.
No new preview shape. Only the blank template endpoint and the tokenless upload.
